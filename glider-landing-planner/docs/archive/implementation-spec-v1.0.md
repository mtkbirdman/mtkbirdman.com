# 1. 目的・スコープ

## 1.1 目的

利用者が地図上でグライダーの離脱地点、着陸地点、滑走路方位、機体性能、風を設定し、**直線・旋回・着陸側の場周プリセットを編集**して飛行経路と高度の推移を比較検討できるWebアプリを作る。離脱側からの順方向設計と、着陸地点側からの逆方向設計を統合し、その間を**滑らかな5次Bezier曲線**で接続する。

成果物はWordPressの固定ページで閲覧・操作でき、計画をブラウザに自動保存し、JSONとしてエクスポート／インポートし、PDF用に印刷できる。

## 1.2 利用対象と責任境界

- 想定利用者：滑空機の教育・訓練・机上検討に関心のあるユーザー。
- 本アプリは飛行力学の**簡易モデル**を使う。機体性能、操縦応答、突風、鉛直気流、乱流、変化する気象、地形障害物、空域、スポイラー性能、フレア等を包括的に評価しない。
- **実際の着陸可否、安全余裕、障害物クリアランスを保証しない。** 総高度余裕が正でも「安全」「着陸可能」と自動表示しない。
- 計算結果にはモデル名・仮定・警告を明示し、PDFにも同じ情報を載せる。

## 1.3 v1.0の範囲（MUST）

1. 日本国内の地図表示、座標指定、距離リング、方位線、風向矢印。
2. 離脱条件・着陸条件・一定風・機体性能の入力。
3. 直線／左右旋回レグの追加・順序変更・編集・削除。
4. **レグ単位**での「機首方位指定」と「対地航跡指定」の切替。
5. プロジェクト共通速度とレグ単位の速度オーバーライド。
6. 離脱側からの順方向設計、着陸側からの逆方向設計。
7. 5次Bezierによる自動接続、接続端の接線・曲率条件、成立性診断。
8. 着陸側のダウンウィンド／ベース／ファイナルのプリセット（左右場周）。
9. 飛行経路、高度プロファイル、各チェックポイントの高度余裕。
10. 沈下モデルA（固定L/D）とB（簡易抗力ポーラー）の選択。
11. Undo/Redo、IndexedDB自動保存、JSON入出力、印刷/PDF保存。
12. WordPressへの独立プラグイン組み込み、PC/スマートフォン対応。

## 1.4 v1.0の対象外（LATER）

- 空域・NOTAM・航空情報の自動取得、障害物回避、実飛行用ナビゲーション。
- 速度変更の動力学（加減速過程・エネルギー交換）、操縦桿入力・機体姿勢6自由度。
- 詳細な実機ポーラー、機体重量変化、密度高度・IAS/TAS変換、バンク移行時のロールレート制約。
- 高度で変化する風、鉛直風、サーマル、乱気流。
- スポイラー操作量と沈下率のモデル、フレア・接地運動。
- DEMに基づく真のAGL／障害物・地形クリアランス保証。
- ユーザーアカウント、サーバー側の計画保存、共同編集、3D表示。

# 2. 採用技術・アーキテクチャ

## 2.1 技術スタック

| 領域 | 採用 | 選定理由 |
|---|---|---|
| 言語 | TypeScript（strict） | 型安全・計算ロジックの保守性 |
| 地図 | Leaflet | 経路・マーカー・操作イベントを利用可能 |
| 地図タイル | 国土地理院・淡色地図（変更可能） | 国内の地図として使いやすい |
| UI | Vanilla TypeScript + CSS | 初期依存を抑える。Reactは必須ではない |
| ビルド | Vite | 開発サーバーと静的アセット生成 |
| 計算 | 自作の純粋関数中心モジュール | UIから切り離し検証可能 |
| テスト | Vitest、Playwright | 数値単体テスト／ブラウザE2E |
| 保存 | IndexedDB + バージョン付きJSON | 無料・サーバー不要・可搬性 |
| PDF | A4横の印刷専用HTML/CSS + ブラウザのPDF保存 | 無料・追加サーバー不要 |
| ブログ | WordPress自作プラグイン | テーマから分離し更新可能 |

依存ライブラリのバージョンは実装開始時に固定し、`package-lock.json`をコミットする。文書中の製品名・APIは参照技術を指定するもので、未確認の「最新版番号」は固定しない。

## 2.2 レイヤー分離

```text
WordPressページ [glider_landing_planner]
  └─ アプリ UI（入力・地図・グラフ・保存操作）
       ├─ Project Store（編集履歴・操作コマンド）
       ├─ Geometry（WGS84/ENU・曲線・弧長・曲率）
       ├─ Flight Engine（風・対地速度・旋回・沈下）
       ├─ Planner（順方向・逆方向・接続・診断）
       └─ IO（スキーマ・IndexedDB・JSON・印刷）
```

原則：`geometry`・`flight`・`planning`はLeaflet、DOM、WordPress、IndexedDBを参照しない。計算エンジンは同一入力に対して同一出力を返す（決定論的）。

## 2.3 ローカル座標系

- 保存・入出力：緯度・経度（WGS84、十進度）、高度MSL（m）。
- 計算：着陸地点付近を原点とする局所**ENU**（East, North, Up）直交座標系。水平座標`eastM`・`northM`はm。
- 緯度・経度の差をそのままmとして扱わない。地球楕円体→ECEF→ENU変換と逆変換を実装・テストする。
- 大規模長距離用途では局所近似の誤差を別途検証する。初期版は滑空場周辺の局所的な着陸経路計画を対象とする。

# 3. UX・画面仕様

## 3.1 主要画面

デスクトップは**左：条件・経路リスト／中央：地図／下：高度グラフ・診断**。スマートフォンでは地図を優先し、条件と結果を折りたたみパネルにする。地図上で選択中のレグと高度グラフ上の対応区間を相互にハイライトする。

### 上部ツールバー

- 新規、プロジェクト名、保存状態、Undo/Redo。
- JSONを開く／書き出す、PDF出力、モデル表示、ヘルプ。
- 高度・距離・速度の単位表示切替。変更しても内部の数値値は変わらない。

### 左側パネル

- 共通設定：機体名（任意）、滑空比／速度、沈下モデル、風向・風速。
- 離脱条件：座標、開始高度、開始機首方位、編集起点。
- 着陸条件：接地点、接地点MSL高度／滑空場標高、滑走路進入方位、目標進入角（初期6°）、直線ファイナル長。
- レグリスト：離脱側、接続区間、着陸側。レグ種別、距離／角度／バンク、風補正方式、個別速度。
- プリセット：左場周、右場周、ダウンウィンド開始、ベース開始、ファイナル開始。

### 地図レイヤー

- 離脱側：青系。接続区間：紫系。着陸側：緑系。
- レグの開始／終了ハンドル、接続点、選択チェックポイント、着陸方向、風向矢印。
- 任意表示：距離リング、方位線、滑走路中心線の延長、制御点、進行方向矢印、背景地図。
- 地図座標と経路編集の精度はズームレベルに依存するため、ドラッグ後にはm単位の結果を示す。

## 3.2 利用者の代表操作

1. 地図上で離脱地点を指定し、開始高度と機首方位を入力する。
2. 接地点・滑走路方位・標高・目標進入角・ファイナル長を指定する。
3. 離脱側に直線、右90°旋回などを順次追加する。
4. 着陸側に標準場周プリセットを配置し、逆方向にレグを追加・編集する。
5. 各レグで「機首方位指定／対地航跡指定」を切り替える。
6. 「滑らか接続」で両端をBezier接続し、接続区間を編集する。
7. 高度グラフ・チェックポイントで余裕／不足と成立性警告を確認する。
8. 計画をJSONで保存し、必要に応じPDFとして印刷する。

## 3.3 編集原則

- **条件の編集が正本**：地図線分の座標は計算結果であり、ドラッグ編集時はレグ長、開始位置、曲線ハンドル等の設計変数を更新する。
- 「直線」「旋回」「ファイナル」「Bezier」は視覚・一覧で区別する。
- レグを挿入・削除・並べ替えたら影響する下流区間を再計算する。
- 逆算側のレグも**実際の飛行方向**で保持・表示する。UIの逆方向編集は入力方式として扱う。
- 不連続・制約違反を黙って補正しない。位置差・方位差・高度差・速度差を診断として表示する。

# 4. 共通モデル・入力定義

## 4.1 基本入力

| 項目 | 内部単位／型 | 初期・制約案 |
|---|---|---|
| 離脱位置 | WGS84緯度・経度 | 地図クリック／数値入力 |
| 開始高度 | m MSL | 入力必須。表示ft/m切替 |
| 開始機首方位 | 度（真北0、時計回り） | 入力必須 |
| 着陸位置 | WGS84緯度・経度 | 地図クリック／数値入力 |
| 着陸標高 | m MSL | 入力必須。暗黙の0mは禁止 |
| 滑走路進入方位 | 度（真方位） | 0以上360未満 |
| 目標進入角 | 度 | 初期6°、変更可能 |
| 直線ファイナル長 | m（対地水平距離） | 入力・ドラッグ編集 |
| 共通速度 | m/s（水平対気速度近似） | UIはkm/h（必要ならkt） |
| 速度上書き | m/sまたはnull | nullで共通速度を継承 |
| 滑空比 | 無次元 | モデルAに使用 |
| 風向 | 度（吹いてくる真方位） | 気象学的な風向定義 |
| 風速 | m/s | 一定の水平風、初期0 |
| レグごとのバンク角 | 度 | 左右・許容上限はユーザー設定値 |
| 高度モデル | enum | AまたはB |

### 高度用語

- **MSL**：平均海面を基準とする高度。内部の正本。
- **滑空場基準高度**：`h_MSL - landingElevationMSLM`。チェックポイントの主な表示候補。
- **真のAGL**：現在地の地表標高との差。地形DEMをまだ持たないv1.0では算出しない／表示しない。
- 地図タイルから地面の高さを自動取得できない場合、利用者が着陸標高を明示入力する。

### 速度の意味

- v1.0の入力速度は、**水平対気速度の大きさ**として扱う簡易モデル。対地速度ではない。
- IASとTASの区別、空気密度補正は扱わない。UIに仮定を明記する。
- レグ間で速度が変化するときは、変更位置で**瞬時に指定速度へ切り替わる理想化**とする。加減速の時間・高度損失・獲得は未モデル化であり警告表示する。

## 4.2 セグメント種別

| 種別 | 必須パラメータ | v1.0での意味 |
|---|---|---|
| `straight` | `lengthM`, `guidanceMode`, `speedOverride` | 指定距離の直線レグ（距離は対地軌跡の弧長） |
| `turn` | `direction`, `angleDeg`, `bankDeg`, `guidanceMode`, `speedOverride` | 協調・一定バンクの左右旋回 |
| `final_approach` | `pathAngleDeg`, `groundLengthM`, `trackDeg` | 対地幾何学的な目標進入経路 |
| `bezier_connector` | 接続する端点、形状パラメータ | 離脱側と着陸側の曲線接続。専用オブジェクト |

直線の「距離」は対地弧長とし、機首方位指定・横風条件でも指定m進むまで積分する。指定時間を基準にするモードは将来拡張とする。旋回の「角度」は機首方位指定では`Δψ`、対地航跡指定では`Δχ`を表す。

# 5. 飛行計算エンジン

## 5.1 風・運動学

東・北座標を`(x,y)`、機首方位を`ψ`（真北から時計回り）、水平対気速度を`V`、風速ベクトルを`(W_E,W_N)`と定義する。水平面では次式を使う。

\[
\dot{x}=V\sin\psi+W_E,\qquad
\dot{y}=V\cos\psi+W_N.
\]

風向入力は「吹いてくる方向」。計算では風が**向かう方向**へ変換する。風は全レグに常時作用し、風補正モードの選択によって無効化しない。

## 5.2 `heading`（機首方位指定）

- 直線：`ψ`を一定に保持する。地上では横風に流され得る。
- 旋回：符号付きバンク角`φ`を一定とし、次の近似式で機首方位を変化させる。

\[
\dot\psi=\frac{g\tan\phi}{V},\qquad
R_{\mathrm{air}}=\frac{V^2}{g|\tan\phi|}.
\]

- 旋回終了条件は指定した機首方位変化量`Δψ`。風下への移流は自然に結果へ反映される。
- バンク移行（ロールイン／ロールアウト）は理想化し、開始・終了部のロールレートは未モデル化。

## 5.3 `ground-track`（対地航跡指定）

- 直線：指定した対地航跡角`χ`を維持する機首方位`ψ`を求める。
- `V_g·t - W`の大きさが`V`に等しい条件を解く。向き`t`への正の対地速度が存在しない場合、**追従不可**を返す。
- 旋回v1.0：一定バンク角で機首方位を積分し、**対地航跡角の変化量`Δχ`**を終端条件とする。地上軌跡は風によって歪む。対地円弧を厳密に追従するモードとは区別する。
- 初期・最終対地航跡角の計算では、角度の0/360跨ぎ、ゼロ対地速度、非単調変化を検出する。
- v1.0では、風補正可能性の簡易条件・数値終端探索を用いる。目標を満たせない場合は終了条件不成立と表示する。

## 5.4 沈下モデルA（固定L/D）

\[
w_A=\frac{V}{E},\qquad E=L/D.
\]

- `w_A`は沈下速度の正値（m/s）。垂直方向の飛行高度変化は`dh/dt=-w_A`。
- 旋回による追加沈下率を**モデル化しない**。計算上は旋回でも同じ沈下速度を使用し、「旋回損失未評価」を結果に付す。
- 速度が異なるレグでは、そのレグの速度に応じて計算する。

## 5.5 沈下モデルB（簡易抗力ポーラー）

定常・浅い滑空角・一定重量・空気密度一定を仮定し、次式を採用する。

\[
w_B(V,\phi)=aV^3+\frac{b\sec^2\phi}{V}.
\]

入力は最大滑空比`E_max`とその達成速度`V_best`（モデル化の基準速度）。係数は、無バンク時の`w/V`が`V_best`で最小値`1/E_max`になる条件から、

\[
a=\frac{1}{2E_{\max}V_{\mathrm{best}}^2},\qquad
b=\frac{V_{\mathrm{best}}^2}{2E_{\max}}.
\]

と置く。この式は教育用の**仮定モデル**であり、実機ポーラーの再現を保証しない。旋回時の荷重倍数を`n≈1/cosφ`として誘導抗力項を増やす。バンクゼロ・`V=V_best`では`V/w_B=E_max`となることを単体テストする。

## 5.6 数値積分

- 初期実装は常微分方程式の**4次Runge–Kutta法（RK4）**とし、経路長や終端角度に応じて刻みを細分する。
- レグ終端ではステップを調整・補間し、指定距離または角度を満たす位置を求める。
- 高度、時刻、ENU位置、機首方位、対地航跡角、対地速度、バンク角、累積水平経路長、警告を各サンプルに保持する。
- 最大ステップ長・刻み数は設定可能にし、テストで収束性を確認する。計算が収束しない場合は数値計算エラーとする。

## 5.7 隣接レグの状態連続性

- 幾何学上の点の接続と、**位置・機首方位・速度・バンク角の連続性**は異なる。
- `heading`→`ground-track`等の切替時は、次のレグが要求する機首方位と前レグ終端との差を算出する。
- 方位やバンク角の瞬間変更が必要な場合は未モデル化として警告する。黙って状態を書き換えない。
- 速度オーバーライドが切り替わる境界も警告対象。将来の「遷移レグ」導入余地を残す。

# 6. 順方向・逆方向の経路設計

## 6.1 順方向

離脱地点の座標・高度・開始機首方位から開始し、`departureLegs[]`を**実際の飛行順**に評価して、各レグの始点・終点・状態系列を生成する。

## 6.2 逆方向

- 着陸地点側でファイナル直線の進入目標条件を定義し、上流側の`arrivalLegs[]`を追加する。
- 保存上の`arrivalLegs[]`は、**ダウンウィンド→ベース→ファイナル**など実際の飛行順に保持する。編集操作だけを着陸側からの逆方向とする。
- 位置・機首方位等の状態の逆算は、順方向と**同じ運動方程式を負の時間方向に積分**する等の方法で実装する。風を符号反転した独立モデルを作らない。
- 地上航跡指定旋回などの逆算は終端条件が絡むため、必要に応じ根探索／シューティング法を使用する。
- 逆算不能・複数解・不確かな解は明示し、見かけ上の曲線で隠さない。

## 6.3 場周プリセット

- 左場周、右場周。ダウンウィンド→ベース→ファイナルの代表レグを生成する。
- 滑走路方位、指定されたレグ長、バンク角、風、目標進入角から幾何・運動を再生成する。
- プリセット値は**編集可能な初期値**であり、正規の航空手順・場周高度を自動保証するものではない。
- ファイナルの目標対地パス角は初期6°だが、ユーザーが任意変更できる。

# 7. 5次Bezier自動接続

## 7.1 接続仕様

離脱側の終点をA、着陸側の始点をBとし、両者間を対地座標の5次Bezier曲線で結ぶ。接続は**水平面（ENU）上の幾何学的経路**とする。

\[
B(t)=\sum_{i=0}^{5}\binom{5}{i}(1-t)^{5-i}t^iP_i,\quad 0\le t\le1.
\]

必須条件：

1. 位置一致：`B(0)=A`、`B(1)=B`。
2. 接線方向一致：両端の接線が隣接レグの**対地航跡接線**と同方向。
3. 曲率一致：両端の**符号付き曲率**が隣接レグの曲率に一致（直線接続なら0）。
4. 地上の軌跡として途中に尖点・不合理な自己交差がないこと。
5. モデルで計算可能な風補正と必要バンク角が、設定条件を満たすこと。

上記は**G²（幾何学的2次）連続**の条件であり、パラメータtに対する2階微分まで連続するC²を無条件には要求しない。これにより、経路形状と積分パラメータを混同しない。

## 7.2 曲線パラメータと探索

- 自動接続の第一案では両端の接線ハンドル長`aM`・`bM`を調整変数とする。
- 直線同士の接続では、例として`P1=A+a tA`、`P2=A+2a tA`、`P3=B-2b tB`、`P4=B-b tB`を初期構造に使用でき、両端曲率を0にできる。
- 曲率非ゼロの端点では2階導関数の**法線成分**を調整して隣接レグ曲率へ一致させる。
- 自動探索は、弧長、曲率最大値、方向変化、自己交差、必要バンク角を評価して候補を選択する。最適値が見つからない場合は「接続候補なし」を返す。
- UIでは形状ハンドルを手動編集できるが、端点の位置・接線・曲率拘束は維持する。

## 7.3 曲線追従と風

Bezierは**対地航跡の形状**として定義する。各弧長位置で接線`t(s)`と曲率`κ(s)`を計算し、指定水平対気速度`V`および一定風`W`に対して、

\[
V_g(s)=W\cdot t(s)+\sqrt{V^2-|W-(W\cdot t)t|^2}
\]

の**前進する正の解**を採用する（平方根が実数で、結果が正の場合のみ）。`V_g t-W`から必要機首方位を求め、曲線上の機首方位変化率から必要バンク角を近似計算する。曲率そのものに対して無風の`R=V²/(g tanφ)`を直接適用しない。

- 必要バンク角の絶対値がユーザー設定上限を超えた場合は制約違反。
- 始終点の機首方位・バンク角・速度の不連続を別途評価。
- v1.0ではバンク変化率・操舵応答を保証しない。**幾何学的接続可**と**動力学的な実飛行可**を混同しない。

## 7.4 弧長・高度損失

Bezierの弧長を`L`、局所対地速度を`V_g(s)`、モデル沈下率を`w(s)`とし、

\[
\Delta h_{AB}=\int_0^{L}\frac{w(s)}{V_g(s)}\,ds.
\]

で接続区間の推定高度損失を求める。数値求積で計算し、弧長／高度損失の刻み依存性をテストする。モデルAでは旋回損失未評価、Bでもロール応答未評価と表示する。

# 8. ファイナルと高度余裕

## 8.1 ファイナルの扱い

- ファイナルは接地点に向かう**指定対地進入角γ**の幾何学的な参照経路として定義する。
- ファイナル開始点の目標高度は、進入終端の参照高度`h_ref`から対地水平距離`d`について、`h_target=h_ref+d·tanγ`とする。
- `h_ref`は着陸標高を基準とする。**フレアはモデル化しない**ため、これは接地まで実際の飛行軌跡を保証する式ではない。
- 要求沈下率は`w_req=V_g·tanγ`。モデルA/Bの自然沈下率との差を表示できるが、スポイラー性能が未入力なら6°維持の実現性は**未判定**とする。

## 8.2 順方向高度と逆算必要高度

- 順方向高度`h_forward(s)`：離脱高度から、直線・旋回・接続区間の**モデル推定沈下**を累積。
- 必要高度`h_required(s)`：終端の目標進入高度を固定し、上流側へ**必要な高度**を逆積算。ファイナル部分は幾何学的目標角を使用し、それ以前は選択モデルの推定沈下を使用。
- チェックポイント高度余裕は`margin=h_forward-h_required`。ft表示では`marginFt=marginM/0.3048`。
- 例：Aでの余裕は`h_forward(A)-loss_connector(A→B)-h_required(B)`。
- 正の余裕：選択したモデル上は**必要高度に対する余剰**。余剰高度を処理できるとは限らない。
- 負の余裕：選択したモデル上の**高度不足**。安全の評価ではない。
- 0に近い場合：計算誤差・モデル不確かさに注意。緑色の「安全」判定をしない。

## 8.3 連続した高度プロファイルの表示条件

水平経路が接続していても、順方向予想高度と着陸側必要高度が一致するとは限らない。差がある場合、グラフでは**順方向の高度線**と**目標高度線**を区別し、差を明示する。未知のスポイラー操作を仮定して両者を黙って接続しない。

## 8.4 チェックポイント

| ポイント | 表示する主な値 |
|---|---|
| 離脱 | 座標、開始高度、速度、機首方位 |
| ダウンウィンド開始 | 順方向高度、必要高度、余裕ft/m |
| ベースターン開始 | 同上、旋回条件 |
| ファイナルターン開始 | 同上、推定バンク角 |
| ファイナル開始 | 目標高度、予想高度、差、要求沈下率 |
| 進入終端 | 参照高度、方向・位置の残差、注意事項 |

# 9. 保存・復元・出力

## 9.1 正式プロジェクト形式：JSON

- UTF-8、拡張子`.glp.json`、MIMEは`application/json`。
- `schemaVersion`と`engineVersion`を保持する。
- 保存対象は**設計入力**（地点、性能、レグ、プリセットから生成された編集可能なレグ、Bezierパラメータ、表示設定等）。
- 描画座標点・サンプル高度は**再計算可能な派生値**とし、正本にはしない。
- インポートではスキーマ、数値範囲、IDの一意性、参照関係、ファイルサイズを検証する。エラーは具体的な項目名で表示する。
- 将来の非互換変更にはバージョン移行関数を設け、未知の上位バージョンは無理に読み込まず安全に拒否する。

## 9.2 IndexedDB自動保存

- 編集確定から約1秒後のデバウンス保存。
- 複数の編集履歴スナップショットを保持し、前回の作業を再開する候補を提示。
- 保存済み／未保存／保存失敗をツールバーに表示。
- ストレージ消去やプライベートモードでは消える可能性があるため、**正式バックアップはJSONエクスポート**と説明する。
- サーバー側にプロジェクト内容を送らないことを初期方針とする。

## 9.3 Undo/Redo

- 操作コマンドまたは不変スナップショットで管理。
- レグ追加・削除・移動・値変更、地点移動、Bezierハンドル変更、プリセット適用を対象とする。
- 自動保存はUndo/Redoとは別。Undo後の現在状態も通常どおり自動保存する。

## 9.4 PDF（印刷）

- v1.0ではA4横・印刷専用レイアウトを提供し、ブラウザの「PDFとして保存」を利用する。
- 内容：タイトル、作成日時、地図／経路図、高度グラフ、主要入力条件、チェックポイント表、制約・警告、出典。
- **最低保証**は経路線・方向・距離リング・高度グラフ等の**ベクター／印刷可能な描画**。背景地図の印刷はブラウザの設定・タイル取得・利用条件に左右されるため、表示可能な場合のみ重ねる。背景なし印刷へ切り替え可能にする。
- 印刷プレビューで欠け・重なりがないことをテストする。
- PDFをJSON代わりの編集形式として扱わない。

## 9.5 将来の出力（LATER）

CSV：位置・時間・高度・速度のサンプル系列。GeoJSON：対地経路のGIS交換。両形式とも**元のレグ設計を完全には再現しない**ことを明示する。

# 10. TypeScriptデータ契約（v1.0）

以下は設計APIの基準となる**型の骨格**である。詳細な値検証はランタイムスキーマで行い、UI固有状態・計算結果は分離する。

```typescript
type GuidanceMode = "heading" | "ground-track";
type Direction = "left" | "right";
type ModelKind = "fixed-ld" | "quadratic-drag";

interface GeoPoint {
  latDeg: number;
  lonDeg: number;
}

interface FlightAnchor extends GeoPoint {
  altitudeMSLM: number;
  headingDeg: number; // 真方位
}

interface PerformanceConfig {
  model: ModelKind;
  fixedLD: number;
  bestLD: number | null;
  bestLDAtMps: number | null;
}

interface WindConfig {
  fromDeg: number;  // 気象風向
  speedMps: number;
}

interface LegBase {
  id: string;
  guidance: GuidanceMode;
  speedOverrideMps: number | null; // null=共通値
  checkpointLabel?: string;
}

interface StraightLeg extends LegBase {
  type: "straight";
  lengthM: number;
}

interface TurnLeg extends LegBase {
  type: "turn";
  direction: Direction;
  angleDeg: number;
  bankDeg: number; // 正の絶対値
}

type FlightLeg = StraightLeg | TurnLeg;

interface FinalApproach {
  type: "final_approach";
  trackDeg: number;
  pathAngleDeg: number;
  groundLengthM: number;
  referenceAltitudeMSLM: number;
}

interface BezierConnector {
  type: "bezier_connector";
  startLegId: string;
  endLegId: string;
  handleStartM: number;
  handleEndM: number;
  curvaturePolicy: "match-neighbors";
}

interface ProjectV1 {
  schemaVersion: "1.0";
  engineVersion: string;
  projectId: string;
  name: string;
  defaultSpeedMps: number;
  performance: PerformanceConfig;
  wind: WindConfig;
  departure: FlightAnchor;
  landing: {
    point: GeoPoint;
    elevationMSLM: number;
    runwayTrackDeg: number;
    final: FinalApproach;
  };
  departureLegs: FlightLeg[];
  arrivalLegs: FlightLeg[]; // 実際の飛行順
  connector: BezierConnector | null;
  display: {
    altitudeUnit: "m" | "ft";
    showDistanceRings: boolean;
    showBearingLines: boolean;
    showWindArrow: boolean;
  };
}
```

**設計上の補足**：`FlightAnchor.headingDeg`は計算の開始状態であり、地上航跡角とは異なる。着陸側の逆算境界でも必要となる場合があるので、`SimulationState`には`headingDeg`・`trackDeg`の両方を保持する。`arrivalLegs`を空から作成する際の開始状態は`FinalApproach`の終端条件から決める。

# 13. 非機能要件

## 13.1 信頼性・再現性

- 同じ入力・同じ`engineVersion`で同じ数値結果を生成する。
- 金額が発生する専用計算APIや地図APIを必須にしない。
- 計算が不成立でもUIが停止しない。入力・編集履歴は保持される。
- 無効なJSONを読み込んでも既存プロジェクトを破壊しない。インポートは検証成功後に適用する。

## 13.2 パフォーマンス

- 通常の滑空場周辺、100レグ・経路サンプル1万点程度を目安としてPC/モバイルで計測する。
- 地図描画はサンプル間引き／更新のデバウンスを許容するが、計算に必要な原系列を破棄しない。
- 数値最適化は反復回数上限とキャンセル可能な設計。UIを長時間ブロックする場合はWeb Workerへ分離する。
- 具体的なms単位の閾値はプロトタイプ計測後に確定する（根拠のない保証値を設けない）。

## 13.3 利用可能性

- キーボードで主要入力を操作できる。ドラッグの代替として数値入力を提供する。
- 色覚に依存せず経路種別と警告を判別できる。
- 表示単位変更は全UI・表・PDFへ整合的に反映する。
- 利用者が入力する任意文字列はテキストとして扱い、HTMLとして注入しない。

## 13.4 セキュリティ・プライバシー

- v1.0ではアカウント不要、設計データのサーバー送信なし。
- JSONインポートはサイズ・構造・数値範囲を制限。外部URL・HTML・スクリプトを実行しない。
- WordPress側のPHPはショートコード登録・静的資産読み込みのみを原則とする。
- 外部ライブラリをロックファイルで管理し、脆弱性情報を確認する。

| T-09 | 順方向→逆方向復元 | 計算条件同一で開始状態へ復帰 |
| T-10 | Bezier両端 | 位置・接線方向・符号付き曲率の拘束一致 |
| T-11 | Bezier弧長 | サンプリング細分による収束を確認 |
| T-12 | モデルBの基準点 | `φ=0`,`V=V_best`で`V/w=E_max` |
| T-13 | 速度オーバーライド | 当該レグにのみ反映。境界警告が出る |
| T-14 | 高度余裕 | `h_forward - h_required`と表示ftが一致 |
| T-15 | JSON往復 | 保存→読込→再計算が同等（順序・ID保持） |
| T-16 | 破損JSON | エラーを表示、現在のプロジェクトを維持 |

数学的許容差（位置m、角度deg、曲率1/m、高度m）は`test-tolerances.ts`に集約し、数値刻み収束テストで設定根拠を記録する。

## 14.2 UI・統合テスト（MUST）

1. 地図上の離脱・着陸地点を編集すると、経路と高度結果が更新される。
2. 各レグで風補正を切り替えると、予期した機首方位／対地航跡の変化が表示される。
3. 逆方向に場周を構成し、Bezier接続を生成・再編集できる。
4. 位置が接続していても方位・バンク・高度が不連続なら、警告を表示する。
5. Undo/Redo、自動保存、ページ再読込後の復元が機能する。
6. JSONエクスポート→別ブラウザ環境へのインポートで同じプロジェクトを開ける。
7. PDF印刷プレビューで経路・高度・条件・出典・警告が欠けない。
8. WordPress固定ページでショートコードが動作し、テーマとCSSが衝突しない。
9. iOS Safari／Android Chrome／主要デスクトップブラウザで基本操作を検証する。

## 14.3 実滑空場での確認

ユーザーが普段使用する滑空場の位置関係・場周経路を、実データで視覚的に確認する。**これは数値モデルの自動テストを代替しない。** 滑空場の座標・標高・場周手順について、アプリが正規情報を保証することはない。

# 16. 設計上の判断・留保事項

| 論点 | v1.0での判断 | 将来の検討 |
|---|---|---|
| Unity | 不採用。2D地図中心のTS/Leaflet | 3D表示が重要になれば別途評価 |
| Bezierの連続性 | G²（曲率一致）で設計 | ロール変化率の動力学的拘束 |
| 風補正 | レグごと。風自体は常時有効 | 高度別風・鉛直風 |
| 速度 | 共通値＋レグ上書き | 速度遷移レグ・エネルギーモデル |
| 高度表示 | MSL・滑空場基準高度 | 地形DEM使用時に真のAGL |
| ファイナル6° | 目標対地幾何角。ブレーキ実現性は未判定 | ブレーキ／フレアモデル |
| 高度余裕 | 予想高度と必要高度の差 | 不確かさを含む評価 |
| 地図印刷 | 経路図を最低保証。背景地図は条件確認 | 地図タイルの確実な印刷方式 |
| 保存 | ローカル＋JSON | サーバー共有・共同編集 |

**実装直前に固定すればよい事項**：採用する依存ライブラリの正確なバージョン、初期プリセットの距離・バンク角、数値積分の刻み・収束許容差、印刷背景地図の扱い、実際のWordPress/PHP環境。これらは基本構造を変えずに調整できる。
