# Glider Landing Planner — WordPress テスト版 v0.1.6

教育・机上検討用のグライダー飛行経路シミュレーターです。実飛行の安全判断には使用できません。

## インストール（FFFTP）
1. 既存の計画は必ず **JSON保存** でバックアップします。
2. ZIPを展開し、`glider-landing-planner` フォルダーを `/public_html/mtkbirdman.com/wp-content/plugins/` へ上書きアップロードします。
3. WordPress 管理画面でプラグイン v0.1.6 を確認します。
4. テストページに `[glider_landing_planner]` を配置し、ブラウザを `Ctrl+F5` で再読込します。

## v0.1.6 の変更
- 計算結果：推定飛行時間と高度余裕を表示。Bezier接続に必要な最大バンクは「計算上の診断」に表示。
- 旋回角の720°入力制限を撤廃。任意の多周旋回を指定可能。極端な角度で計算負荷が高い場合は `TURN_COMPLEXITY_LIMIT` を発し、無制限実行しない。
- Bezier接続は自動調整を基本とし、経路形状・速度・風の変更時に最適化。制御ハンドルをドラッグすると手動調整モードへ切替。
- 距離リング・方位線の不透明度を統合し、距離リング間隔／方位線間隔／磁気偏角を追加。偏角は東偏＋・西偏−、**地図補助方位線のみ**に適用。飛行計算と滑走路・風入力は真方位基準。
- Bezierハンドルの数値入力欄を廃止。JSON内の制御長は継続保持。
- PDF印刷の右側灰色余白を白色に変更。診断セクションの見出し重複を解消。

## 補足
- 古いJSON・IndexedDBの `distanceRingOpacity` と `bearingLineOpacity` は読込可能です。新しい `referenceLineOpacity` の初期値は旧距離リング側の値を継承します。旧フィールドは過去のバックアップのための互換データです。
- 地図タイルのPDF表示はネットワーク・ブラウザの印刷動作に依存します。印刷プレビューで背景地図・出典・高度ラベルを確認してください。
- 自動接続は制約を必ず満たすとは限りません。連続性、風、荷重倍数・バンク制約などの警告に従ってください。
- 既存のWordPressショートコード、プラグインディレクトリ名は変わりません。

## 開発者向け
`source/` にTypeScriptソースとNode.jsテストを同梱しています。ビルド：`cd source && npm run build:offline`。テスト：`npm test`。

- **互換性**：`schemaVersion: "1.0"` とショートコード `[glider_landing_planner]` を維持。URL・PHPプラグインフォルダー名は変更しません。

# Glider Landing Planner v0.1.3 — WordPressテスト版

## v0.1.3 の変更（2026-11-23）

- **地図上のチェックポイント高度**：常時表示ラベルは `1,535 ft` のように数値＋単位のみ。WordPress/Cocoonによる縦方向折返しを避けるため、ツールチップと内部要素を横書き・折返し禁止に設定。ダウンウィンド高度余裕は別行の表示を維持。ラベルが近接した際の重なりは今後の改善対象です。

- **離脱高度・着陸標高の入力**：表示単位 `ft` をデフォルトとし、基本条件で `ft/m` を切替可能。値はMSL基準。JSONと内部計算の高度は引き続きm単位で保持し、表示・入力時だけ変換します。旧JSONのm設定は尊重します。
- 自動テスト **32件** 成功。TypeScriptビルド・PHP構文チェック済み。

# Glider Landing Planner — WordPress テスト版 v0.1.0

教育・机上検討用のグライダー着陸経路計画アプリです。

**このZIPはそのままWordPressのプラグインとしてインストールできます。** `source` 内にTypeScriptソースコードと数値テストを同梱しています。WordPressのサーバー側にNode.jsやTypeScriptは不要です。

## 1. FFFTPでの導入（推奨手順）

1. WordPressサイトとFFFTPの接続情報を、現在のブログで利用中のものとします。このプラグインに認証情報を入力する機能はありません。
2. 配布ZIPを**PC上で展開**してください。展開後に `glider-landing-planner` フォルダーができます。
3. FFFTPで接続し、WordPress本体が配置されているディレクトリを開きます。`wp-content/plugins/` へ移動してください。
4. **`glider-landing-planner` フォルダー全体**を `wp-content/plugins/` にアップロードします。`glider-landing-planner.php` が `wp-content/plugins/glider-landing-planner/glider-landing-planner.php` に位置していることを確認してください（二重階層にしない）。
5. WordPress管理画面 → **プラグイン** → **インストール済みプラグイン** → **Glider Landing Planner** を **有効化**します。
6. WordPress管理画面 → **固定ページ** → **新規固定ページ**。タイトル例：`グライダー着陸経路シミュレーター（テスト）`。本文に「ショートコード」ブロックを置き、次を1行で入力します。

       [glider_landing_planner]

7. 最初は「非公開」または「パスワード保護」で公開し、ブラウザで表示を確認します。
8. 画面上部の **JSON保存** でバックアップを取りながら操作してください。

**WordPress管理画面からでもインストール可能：** プラグイン → 新規プラグインを追加 → プラグインのアップロード → このZIPを指定 → インストール → 有効化。

### FFFTP操作上の注意

- **FFFTPはZIPをサーバー上で自動解凍しません。** FFFTP利用時にはPC上で解凍したフォルダーを転送してください。
- 別のテスト版へ更新する場合は、先にバックアップを取り、同じフォルダー内のファイルを更新してください。作成したプロジェクトはブラウザ側のIndexedDBとJSONにあり、サーバー側では保存していません。
- 文字コードはファイル側でUTF-8です。転送は**バイナリモード**を推奨します（JavaScript/CSS/PHPが変換されないように）。
- ZIPにはソースが入っていますが、公開サーバーで必要なものは `glider-landing-planner.php` と `assets/` です。ソースを公開したくない場合は `source/`, `docs/`, `preview-local.html` をアップロード対象から外して構いません。

## 2. 動作前提

- WordPress（一般的な自前レンタルサーバー版）、PHP 7.4以降、HTTPSのサイト。
- JavaScript ES modules/IndexedDBに対応した新しいPC/スマートフォンブラウザ。
- ネット接続：**Leaflet 1.9.4 のJS/CSSを unpkg.com から読み込みます**。地図タイルは地理院サーバーからHTTPSで読み込みます（両配信先への接続が必要）。地図以外の飛行計算とJSONはサイト閲覧者のブラウザ内で行います。
- CDNアクセスが禁止されている場合は地図が表示されません。ドメインブロックや厳しいCSPが原因の可能性があります。
- 1固定ページにショートコード1個を想定。テーマ・プラグインとの競合は実サイトで確認してください。

## 3. テストの推奨順序

1. 地図が表示され、凡例・離脱/接地点のマーカーが見えること。最初の地点・標高は**架空の動作確認用入力**です。
2. 離脱地点と着陸地点のマーカーをドラッグし、経路が再計算されること。
3. 離脱側に直線・旋回レグを追加し、クリックで編集欄を開くこと。レグごとに機首方位／対地航跡モードを切り替えること。
4. 左場周・右場周を選び、着陸側経路が逆算されること。
5. **曲線を自動調整**を押し、接続区間・チェックポイント・警告が更新されること。
6. 基本速度とレグ個別速度、風向・風速、モデルA/Bを変えること。
7. **JSON保存 → JSON読込**で同じ設計が再現されること。ブラウザを再読込した際に自動保存の復元案内が出ること。
8. **PDF印刷**を押して印刷ダイアログを開き、「PDFに保存」を選択すること。PDFは**背景地図を含まないベクター経路図**を優先しています。
9. PC・iPhone等の画面で余白・ボタン・地図高さを確認すること。

## 4. 実装している機能

- 日本国内の地理院タイル＋Leaflet、経路の色分け、方位線・距離リング、風矢印、マーカー・直線レグ長・Bezierハンドルのドラッグ。
- 離脱側の順方向／着陸側の逆方向、左右場周プリセット。
- 直線と旋回の各レグに `heading` / `ground-track`、直線の指定方位、レグ個別速度。
- 旋回は一定バンク・数値積分（RK4）、固定L/D(A)と簡易抗力モデル(B)。
- 5次Bezier、接続端の位置・接線・符号付き曲率一致、形状に沿った対地速度・バンク角・沈下積分、簡易探索と警告。
- 必要高度・予想到達高度の別系列表示、チェックポイントの高度差、ファイナル目標6°の比較。
- Undo/Redo、IndexedDB直近10世代、バージョン付きJSON、ブラウザ印刷用A4横。

## 5. 制約・未完了事項（重要）

**このZIPは、仕様書v1.0の完成版ではなく、検証用v0.1です。** 数値計算の単体テストは実施していますが、実際のWordPressサイトでのブラウザ操作とFFFTP転送は、この環境では実施できていません。

- 旋回の対地航跡指定は**終端の対地航跡角**を指定する方式であり、一定半径の地上円弧を厳密に追従する制御ではありません。
- 旋回中のロールイン／ロールアウト、レグ間速度変化の加減速、気流変化、スポイラー、フレア、地形・障害物は未モデル化です。
- Bezierは幾何学的なG²接続と必要バンク角の簡易判定です。形状探索は有限候補の近似で、可能な経路を必ず発見できるわけではありません。
- 地図ドラッグで編集できるのは地点、直線レグ長、ファイナル長、Bezierハンドルです。**旋回レグそのものの自由なドラッグ編集**はまだ数値欄での編集に限定しています。
- JSONのエンジンバージョンを記録しますが、将来バージョンの自動移行はまだありません。
- PDFは「ブラウザの印刷／PDFとして保存」方式で、自動PDFバイナリ生成ではありません。背景地図画像のPDF転記は行いません。
- AGL（現在地の地形標高との差）は未対応です。MSLと着陸地点基準高度を混同しないでください。
- 本アプリの高度余裕は、選択した簡易モデルに対する**推定余剰／不足**です。実飛行の安全余裕や着陸成立を保証しません。
- 配布JSはTypeScriptコンパイラーによるES modules出力です。Viteによる本番バンドルは現段階では未使用です（下記参照）。

## 6. 開発者向けソースとテスト

- `source/src/`：TypeScriptソース。
- `assets/js/`：配布用にコンパイル済みのES modules。ブラウザはこれらを直接参照します。
- `source/tests/engine.test.mjs`：19の数値・JSONテスト。別途Node.js 22以降を準備してプラグインディレクトリに移動後、`node --experimental-default-type=module --test source/tests/engine.test.mjs`。
- `source/tsconfig.json`：TypeScript strict、ES2022。
- `docs/implementation-spec-v1.0.md`：合意した詳細仕様書。

再ビルド例：`cd source` → `tsc -p tsconfig.json`。`tsc`がない場合はTypeScriptを別途インストールしてください。WordPressへの導入や日常的な試用にはこの作業は不要です。

Viteの採用を想定した開発設計ですが、配布ZIPの生成時は外部npmレジストリに接続できなかったため、**今回はTypeScriptコンパイラーで生成**しています。Viteの依存管理・本番バンドル・Playwright E2Eは今後の開発工程です。虚偽の `package-lock.json` は同梱していません。
