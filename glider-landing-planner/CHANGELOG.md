# 変更履歴 — Glider Landing Planner

過去のリリースで**何が変更されたか**を示します。現在の操作は[README](README.md)、実装構造は[DEVELOPMENT](docs/DEVELOPMENT.md)、現行の数式は[THEORY](docs/THEORY.md)を参照してください。

分類：**Added**（追加）、**Changed**（変更）、**Fixed**（修正）、**Removed**（削除）、**Compatibility**（データ・動作互換性）。v0.1.16以前の日付は元の配布READMEに記載された日付です。v0.1.7〜v0.1.9、v0.1.6の詳細な公開日付は当該記録から確定できません。

## [1.0.0] — 2026-11-27

### Changed
- 初回正式公開版。画面・PDF・PHP・パッケージ・アセットの版数を1.0.0に統一し、テスト版表記を除去。
- 公開URLをREADMEに設定。配布物の不要な生成物を除外し、開発用のビルドと配布済みZIPの反映を分離。

### Fixed
- GLP-019：Bezier接続の対地速度下限を、解析的下界と導関数凸包の有限分割で全区間について保守的に評価。違反・判定不能は不成立とし、編集用形状は保持する。
- GLP-020：着陸地点を基準とした連続経度で地図の経路・マーカー・全体表示を統一。地図クリックとハンドル操作で保存・計算用経度に正規化。

### Added
- 既存のGPL-2.0-or-later宣言に対応するライセンス本文（LICENSE）。

### Compatibility
- 基本物理モデル、既定値、数値積分方式、JSONスキーマ1.3、内部識別子、IndexedDB、ショートコードを維持。極端な風条件では新しい成立判定により従来成立した曲線が不成立になる場合がある。

## [0.1.21] — 2026-11-26

### Changed
- 飛行方式を「機首方位指定」「航跡方位指定」に統一し、直線の方位欄・診断・印刷用HTMLも用語を揃えた。
- 旋回角の入力方式と数値欄を「旋回角を指定」「旋回角」に統一。方位指定では離脱側の「旋回後の…を指定」、着陸側の「旋回前の…を指定」を明示する。
- README・DEVELOPMENT・再構成済みTHEORY（SVG図7点を含む）を現行用語に更新。

### Compatibility
- 計算式・計算条件・既定値・JSONスキーマ1.3・内部識別子・IndexedDB構造は変更なし。今回の対象は用語と文書のみ（GLP-019・020の計算／描画修正は含まない）。

## [0.1.20] — 2026-11-26

### Fixed
- GLP-015: Bezier導関数の凸包性と有限分割で正則性を確認。未確認の曲線は飛行計算せず編集用プレビューを保持。
- GLP-016: 未完了レグの正式チェックポイントを除外し、地図では破線表示。PDFの解決済み旋回角は完了レグに限定。
- GLP-017: ハンドル長の保存範囲を共有し、自動候補・ドラッグ・編集確定後のデータを検証。
- GLP-018: レグIDのHTML属性出力を安全化し、特殊文字を含むIDの同一性を保持。

### Compatibility
- 航空工学モデル、計算適用範囲、JSONスキーマ1.3、IndexedDBの構造は変更なし。

### Verification
- Node.js 22.16.0 / TypeScript 5.8.3: 175件の自動テスト成功。実ブラウザ・WordPressでの受入は未完了。

## [0.1.19] — 2026-11-26

- ファイナル速度・風補正を直前レグの実効速度に統一。
- 着陸側逆算経路を正本化し、再積分せず予想高度を構築。結果指標を全制約評価後に確定。
- 進行方向指定の風条件、対地速度、沈下率比、局所ENUの適用範囲とサンプル予算を管理。
- Bezier境界・最大必要バンクの追加評価・自己交差・次候補再評価を改善。
- JSONの列挙値・必須値を厳密に検証。正常なスキーマ1.3は互換。旧版で受理された異常条件は不成立となる場合がある。
- 未設計／不成立／計算成立を区別。実飛行の安全性を評価するものではない。

## [0.1.18] — 2026-11-26

- **Changed:** 利用者向けの飛行方式を「機首方位指定」「進行方向指定」に統一。直線・旋回編集では指定する物理量と旋回前後を明示し、PDFの飛行方式表記も統一。
- **Changed:** 手動追加する離脱側・着陸側の直線・旋回の既定の飛行方式を `ground-track`（進行方向指定）に変更。場周プリセットは従来どおり。
- **Fixed:** 風向表示に風下方向を指す矢じりを追加。表示位置・全長・色・無風時の非表示は維持。
- **Fixed:** Node.js 24で廃止されたテスト起動オプションを除去し、`source/.gitignore`で `node_modules/` を除外。
- **Compatibility:** JSONスキーマ1.3、既存レグの飛行方式、飛行計算式、スマートフォンのレイアウトは変更しない。

## [0.1.17] — 2026-11-25

- **Changed:** 新規計画の初期座標・標高・離脱高度・機首方位・進入真方位を更新。直線ファイナル長は600 m。高度差1200 ft、速度・風・性能設定、未設計状態は維持。
- **Removed:** 速度別ポーラーモデル（旧モデルC）、モデル選択、ポーラー入力・補間・旋回補正・専用診断、旧形式の移行・補完処理を削除。旧モデルBの簡易抗力式を唯一の沈下率計算として維持。
- **Changed:** 性能設定を `bestLD` と `bestLDAtMps` に統一し、PDFにも両値を表示。沈下率モジュールを `flight/sink.ts` に改名。
- **Compatibility (breaking):** JSONスキーマ1.3のみ対応。1.0〜1.2のJSON・自動保存は読込不可。旧データは強制削除せず、復元不能時は新規計画を表示。WordPress更新時は廃止済みの `assets/js/flight/polar.js` を削除する。

## [0.1.16] — 2026-11-25

- **Changed:** 新規計画を離脱側レグ0件・着陸側レグ0件・Bezier接続なしで開始。離脱側の青い250 m方向ガイドは計算対象外。着陸側の450 m直線ファイナルは緑の破線で表示。
- **Added:** 離脱側0件では「離」マーカーを初回レグ追加の入口に変更。最初のレグ追加で先端「＋」を表示。着陸側の最初のレグ追加／左右場周プリセットでBezierを生成。
- **Changed:** 未設計時は距離・時間・高度余裕を「—」、グラフを未設計案内とし、未設計だけで接続エラーを出さない。「着」マーカーからファイナルとプリセットを編集。
- **Compatibility:** JSONスキーマ1.2、既存JSON・IndexedDBのレグと接続設定、計算モデルB/C、PDF構造は変更なし。既存保存計画を新規状態へ強制リセットしない。

## [0.1.15] — 2026-11-25

- **Added:** PCで地図の地点・レグ選択時に、対応する左サイドバー編集欄へスクロール。経路端の「＋」からレグ追加、選択レグの削除ボタンを追加。
- **Removed:** 地図上での離脱・着陸地点、直線距離「↔」、ファイナル長「F」のドラッグ編集。地図背景の移動とBezierハンドルのドラッグは継続。
- **Changed:** 印刷地図からPC用の追加ポップアップを除外。
- **Compatibility:** JSONスキーマ1.2、飛行計算・接続モデル・PDF基本構成は維持。

## [0.1.14] — 2026-11-25

- **Removed:** 廃止済み沈下モデルA（`fixed-ld`）の承認・変換・専用バックアップ機能。
- **Compatibility:** **旧モデルAを使用するJSON／自動保存は読込不可**。モデルBのスキーマ1.0、およびB/Cの1.1/1.2は引き続き対応。既存の旧バックアップ用IndexedDBストアを消去する処理は追加していない。
- **Changed:** 旋回の読取専用欄から「（自動計算）」の文言を削除（値の算出処理は維持）。

## [0.1.13] — 2026-11-25

- **Added:** 旋回の排他的な入力方式「旋回角を指定／目標方位を指定」。離脱側は旋回後、着陸側は旋回前の真方位を入力。最近の角度に近い正の解を選び多周旋回を維持。
- **Changed:** 逆算した着陸側の実効旋回角を順方向の高度計算にも用い、一覧・PDFへ計算結果を表示。
- **Compatibility:** **JSONスキーマ1.2**へ変更。1.0/1.1の旋回は「旋回角指定」として読み込む。

## [0.1.12] — 2026-11-25

- **Added:** 速度別ポーラーの**モデルC**。4〜64点の速度・沈下率データをPCHIPで補間し、データ範囲外は外挿しない。入力内容は「ポーラーを適用」で確定する。
- **Changed:** 簡易抗力**モデルB**を新規計画の標準へ設定。B/Cのパラメータは別々に保持。
- **Compatibility:** 当時JSONスキーマ1.1へ変更し、モデルBのスキーマ1.0からの移行処理を導入（v0.1.13で1.2へ変更）。

## [0.1.11] — 2026-11-24

- **Changed:** 新規計画の地図中心・ズーム14と、既存計画読込時の全体表示を区別。
- **Compatibility:** 保存済みJSON／IndexedDBの地点・条件は新規計画の仮値で上書きしない。

## 保存データ互換性の要点（現行v1.0.0）

| 保存データ | 読込 | 備考 |
|---|---|---|
| スキーマ1.3 | 対応 | 現行保存形式 |
| スキーマ1.0〜1.2 | 非対応 | モデルを問わず移行しない |
| 将来の未知スキーマ | 非対応 | 推測による変換をしない |

旧形式の計画を利用するには対応する旧バージョンが必要です。
